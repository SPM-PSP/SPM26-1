# 多智能体在线语音狼人杀系统测试计划书

## 1 总论

### 1.1 文档目的

本测试计划用于指导《多智能体在线语音狼人杀系统》的测试工作开展，明确测试目标、测试范围、测试策略、测试方法、测试资源以及测试组织安排，为后续测试实施提供统一依据。

本文档主要用于说明测试活动在执行前如何规划、组织和控制；测试执行结果、缺陷记录、命令输出和最终结论以测试报告及各模块单元测试报告为准。

本文档主要面向测试负责人、开发人员及项目组成员，具体目的如下：

- 明确系统测试范围及测试对象；
- 规范测试活动组织流程；
- 指导测试用例设计与测试执行；
- 保证系统功能需求、接口需求及性能需求得到充分验证；
- 为后续测试报告编写提供依据；
- 为项目验收提供测试支撑材料。

### 1.2 项目概述

本项目是一个基于 Web 的多智能体在线语音狼人杀系统，支持玩家登录、房间创建与加入、多人实时对局、角色技能结算、投票放逐、AI 玩家参与、语音 STT/TTS 交互以及赛后 AI 智能复盘。

当前代码实现采用前后端分离与外部智能服务协同的方式：

| 层次 | 当前实现 | 主要说明 |
|---|---|---|
| 前端交互层 | Vue 3/Vite 复盘展示页；`frontend/client` 保留主游戏前端源码 | 提供登录、房间、游戏桌面、语音交互和复盘展示能力 |
| 后端业务层 | Node.js + Koa 2 + Sequelize + MySQL | 负责用户鉴权、房间管理、游戏状态机、技能结算、投票、日志、AI/语音/复盘调度 |
| 实时通信 | nodejs-websocket | 负责房间状态、阶段变化、发言、投票和结算广播 |
| AI Agent 服务 | Python + FastAPI | 负责 AI 玩家生成、角色同步、人格、记忆、Prompt、阶段决策、多狼人共识 |
| 语音服务适配 | Koa 后端 `voiceController` / `voiceService` 调用火山引擎 STT/TTS | 负责语音转文本、文本转语音和语音发言提交 |
| AI 复盘服务 | Python 复盘 HTTP 服务与本地复盘文件输出 | 负责根据游戏日志生成结构化复盘结果和文本报告 |
| 数据存储 | MySQL 与本地文件 | MySQL 保存用户、房间、游戏、玩家、行动、记录等数据；AI 记忆和复盘结果使用本地文件目录 |

### 1.3 测试目标

本项目测试目标包括：

- 验证用户注册登录、房间管理、玩家入座、房主控制等基础功能正确；
- 验证狼人杀游戏流程、角色分配、昼夜阶段、技能使用、投票放逐和胜负判定符合需求；
- 验证 AI 玩家能够完成生成、角色同步、记忆维护、发言、投票、夜晚行动和多 AI 狼人协同；
- 验证 STT/TTS 语音能力和发言阶段、发言轮次、游戏日志之间的关联；
- 验证 AI 复盘能够基于游戏记录生成可展示的分析结果；
- 验证 REST API、WebSocket、AI Service、语音服务和复盘服务接口结构正确；
- 验证异常输入、越权操作、外部服务不可用、断线重连等场景下系统具备容错能力；
- 验证需求文档、系统设计文档、接口文档、代码实现和测试报告之间保持一致。


## 2 项目测试流程

### 2.1 测试过程

本项目测试过程按照从需求到报告的顺序组织，测试执行中发现的问题进入缺陷跟踪与回归验证流程。

```text
需求分析
   ↓
测试计划制定
   ↓
测试用例设计
   ↓
测试环境搭建
   ↓
测试执行
   ↓
缺陷记录
   ↓
缺陷修复
   ↓
回归测试
   ↓
测试报告
```

各环节说明如下：

| 环节 | 主要工作 | 产出 |
|---|---|---|
| 需求分析 | 阅读需求分析文档，识别功能、接口、性能和异常场景 | 测试范围、需求跟踪关系 |
| 测试计划制定 | 明确测试目标、方法、资源、人员与进度 | `测试计划书.md` |
| 测试用例设计 | 按模块设计功能、接口、性能、自由操作和文档一致性用例 | 测试报告中的用例表 |
| 测试环境搭建 | 准备前端、后端、MySQL、AI Service、复盘服务、语音配置 | 可执行测试环境 |
| 测试执行 | 执行自动化单元测试、接口测试、功能测试和异常场景测试 | 测试记录、命令输出 |
| 缺陷记录 | 记录失败用例、复现步骤、影响范围和严重级别 | 缺陷跟踪表 |
| 缺陷修复 | 开发人员修复代码或文档并说明变更点 | 修复记录、提交记录 |
| 回归测试 | 对修复点和相关主流程重新验证 | 回归结果 |
| 测试报告 | 汇总测试范围、过程、结果、缺陷和结论 | `测试报告.md` |

### 3.2 测试用例设计

本项目测试用例设计主要采用黑盒测试方法，并结合狼人杀业务特点进行场景化设计；对于 AI、后端服务和前端工具函数等内部逻辑，补充自动化单元测试，验证函数、类和 service 方法在固定输入下的行为。

测试用例设计遵循以下原则：

- 功能覆盖原则：每项核心功能需求至少设计正常路径用例；
- 边界值原则：覆盖人数、阶段、存活状态、空输入、非法目标等边界；
- 异常场景原则：覆盖未登录、越权、重复提交、服务不可用、模型调用失败等异常；
- 用户行为原则：按玩家、房主、AI 玩家、观战者等角色设计真实操作路径；
- 回归验证原则：对历史缺陷、修复点和高风险模块设计回归检查；
- 非确定性结果弱断言原则：AI 文本、语音识别等非确定性输出不要求全文一致，重点验证字段合法、非空、目标合法和敏感信息不泄露。

- 用户登录；
- 房间管理；
- 游戏流程；
- 技能结算；
- 投票放逐；
- 胜负判定；
- AI 行为；

#### 3.4.2 性能测试

性能测试用于验证系统在典型使用场景下的响应速度和稳定性，重点覆盖：

- 页面加载速度；
- REST API 响应时间；
- WebSocket 稳定性；
- STT 响应时间；
- TTS 响应时间；
- AI 推理耗时；
- 多房间并发能力；
- 外部服务超时对主流程的影响。

#### 3.4.3 接口测试

接口测试用于验证系统内部和外部接口的请求方法、参数、响应格式和异常处理是否正确，重点覆盖：

- REST 接口；
- 后端业务接口；
- AI Service 接口；
- WebSocket 接口；
- 语音 STT/TTS 接口；
- AI 复盘接口；
- Token 鉴权和权限校验；
- 参数缺失、非法目标、非法阶段等异常响应。

#### 3.4.4 文档一致性测试

文档一致性测试用于验证项目文档与实际代码实现是否一致，重点覆盖：

- SRS；
- SDD；
- API 文档；
- README；
- 项目代码目录；
- 启动命令；
- 依赖文件；
- 测试报告。

#### 3.4.5 自由操作测试

自由操作测试用于模拟用户非标准操作和外部服务异常，重点覆盖：

- 重复投票；
- 非法技能；
- 非法阶段操作；
- 未登录访问鉴权接口；
- 非本人轮次发言；
- AI 服务关闭；
- 语音服务关闭；
- 复盘服务关闭；
- 网络断开；
- 页面刷新与断线恢复。

### 3.5 自动化单元测试计划

| 模块 | 测试框架/命令 | 测试重点 |
|---|---|---|
| 前端模块 | `npm run test:frontend` | 登录、房间、游戏操作、语音 API 封装、复盘页面数据解析 |
| 后端模块 | `npm.cmd run test:backend` | 响应封装、密码和 Token、鉴权中间件、用户/房间服务、胜负判定、复盘触发 |
| AI 模块 | `cd 代码/AI-Wolf && python -m pytest tests/test_ai_player.py -q` | AI 初始化、角色管理、记忆、Prompt、模型解析、异常兜底、多狼人协同 |

自动化单元测试原则：

- 不真实调用外部大模型 API；
- 不真实连接生产数据库；
- 不依赖真实前后端页面或完整房间服务；
- 使用 mock、stub、内存仓库或固定数据替代外部依赖；
- 对 AI 文本不做完整字符串相等断言，只验证格式、合法性和敏感信息过滤。

| 级别 | 说明 | 示例 |
